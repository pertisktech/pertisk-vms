pertisk-vm — phases and tasks
=============================

MVP = phases 0–4 on one Linux/KVM node.
Cluster = phase 5. HCI storage = phase 6 (optional).
Bare-metal installer ISO = phase 7 (Proxmox-style flash; after the control plane).


Phase 0 — Foundations
---------------------
Goal:  decisions and repo so later work does not thrash
Demo:  workspace builds; /dev/kvm works; VMM binary runs a manual VM
Skip:  API, Ceph, cluster protocol

  [x] Confirm /dev/kvm, CPU virt flags, nested virt
  [x] Pick VMM: Cloud Hypervisor (Linux) or QEMU (Windows/PCI)
  [x] Cargo workspace: types, vmm, storage, net, daemon, api, cli
  [x] VM/disk/net IDs, spec structs, host config file
  [x] Install VMM and boot one manual test VM
      proof:  AlmaLinux KVM, scripts/linux-guest.sh → Alpine 3.21 login on ttyS0
      (this Mac checkout is still mock-only; no /dev/kvm)


Phase 1 — VM lifecycle                         → v0.1 hypervisor node
---------------------
Goal:  create / start / stop / destroy on one node
Demo:  CLI boots Alpine; list shows running; stop is clean
Skip:  UI, cluster, snapshots, SDN

  [x] VmmDriver trait: create, start, stop, destroy, status
  [x] Cloud Hypervisor adapter (unix-socket HTTP); QEMU QMP later
  [x] VM spec: vCPU, RAM, kernel or disk, serial log
  [x] Persist VM records (JSON/SQLite) with socket/pid paths
  [x] CLI: pertisk vm create | start | stop | rm | list | show
  [x] Integration test: boot, serial output, shutdown


Phase 2 — Disks and images
--------------------------
Goal:  volumes operators expect
Demo:  clone a template, attach ISO, boot installer
Skip:  Ceph / vSAN / custom distributed FS

  [x] Local directory volume store (raw + qcow2)
  [x] Create / resize / delete; attach virtio-block
  [x] ISO library + CD-ROM attach
  [x] qcow2 snapshot + restore
  [x] Linked clone from template
  [ ] Optional ZFS dataset backend


Phase 3 — Network and console
-----------------------------
Goal:  guest on a virtual network; operator can open a console
Demo:  SSH into guest; serial or VNC from host
Skip:  NSX / EVPN / multi-tenant overlay

  [x] Linux bridge (vmbr0) — real `ip` on Linux, inventory on macOS
  [x] Per-VM TAP + virtio-net; cleanup on destroy
  [x] Static IP or IPAM pool (dnsmasq daemon not started)
  [x] Basic isolation (Linux `bridge link isolated`)
  [x] Serial console log + attach
  [x] VNC or websocket console proxy


Phase 4 — API, auth, UI                        → v1.0 single-node platform
-----------------------
Goal:  operators never SSH to the hypervisor (this is the product)
Demo:  browser creates VM from ISO, watches task, opens console
Skip:  UI without a strict API

  [x] REST: /vms /volumes /networks /tasks + OpenAPI
  [x] Inventory DB (SQLite first)
  [x] Tokens, users, roles (admin / operator / viewer)
  [x] Async task log (clone, start, backup)
  [x] Audit events
  [x] Web UI: inventory, create wizard, console, tasks


Phase 5 — Cluster, HA, migrate                 → v2.0 cluster
------------------------------
Goal:  more than one box
Demo:  3 nodes; kill one; VMs restart elsewhere
Skip:  fancy DRS before quorum and fencing

  [x] Node agent: heartbeat, local VMs, CPU/RAM/disk
  [x] Join/leave; shared inventory
  [x] Quorum + fencing (no split-brain)
  [x] HA restart on node loss
  [x] Live migration via VMM
  [x] Simple scheduler: least-loaded node that fits


Phase 6 — Distributed storage                  (optional, last)
-----------------------------
Goal:  one pool across nodes (Nutanix/vSAN class)
Demo:  VM disk survives node loss without copying files
Skip:  starting the whole project here

  [x] Ceph RBD (optional; `rbd` CLI) + replica file backend (default)
  [x] Replica placement + rebuild
  [x] Thin provision, snapshots, clones on shared storage
  [x] Storage-aware live migrate / HA (prefer replica holders)


Phase 7 — Installer ISO                         → v3.0 flashable node
-----------------------
Goal:  USB/ISO boots the 9955HX (or any x86_64 box); after install, UI manages VMs
Demo:  flash ISO → install to disk → reboot → http://<host>:7480/ creates a guest
Skip:  writing a hypervisor; Windows/graphical guest VGA (still Cloud Hypervisor serial)

This is a Linux installer image that ships pertisk, not a new VMM.
Today you can `sudo ./scripts/install-node.sh` on Linux KVM. `./scripts/build-iso.sh` (mkosi) builds a flashable ISO.

  [x] Pick base: Debian bookworm via mkosi (not a custom kernel)
  [x] Image contents: Linux + KVM + cloud-hypervisor + hypervisor-fw + pertiskd + CLI
  [x] systemd: pertiskd on boot, listen 0.0.0.0:7480, bootstrap admin password
  [x] Installer: disk layout (EFI + root); `pertisk-install --list` / `--disk … --yes`
  [x] Build pipeline: `scripts/build-iso.sh` → `out/pertisk-node.iso` (x86_64; Linux + mkosi)
  [x] First-boot: TTY/issue + `/etc/pertisk/admin`; optional join via `/etc/pertisk/join`
  [x] Hardware check: SVM/VMX + `/dev/kvm` (`pertisk-kvm-check`; install refuses without it)
  [x] Flash helper: `scripts/flash.sh` (refuses to wipe the running root)
  [ ] Proof: one box (e.g. 16c/64G) flashed from USB, Alpine guest via serial


Crate map
---------
pertisk-types     IDs, spec, errors          all phases
pertisk-vmm       CH / QEMU adapters         phase 1
pertisk-storage   volumes, snapshots, ISO    phase 2
pertisk-net       bridge, TAP, DHCP          phase 3
pertisk-daemon    node agent, reconcile      phases 1 and 5
pertisk-api       HTTP, auth, tasks          phase 4
pertisk-cli       operator CLI               phase 1 onward
iso/image         live + installer (scripts) phase 7


Release gates
-------------
Crate version today is 0.1.0. Gates below are product proofs, not cargo semver.

v0.1  phases 0–1   CLI starts/stops a VM
      done:   mock/CH driver, persist, CLI create/start/stop/rm, integration test
      proof:  Alpine 3.21 on Linux KVM via Cloud Hypervisor (scripts/linux-guest.sh)

v1.0  phases 2–4   disks + net + console + API + UI  (one-node operator)
      done:   volumes (create/resize/clone/snap), ISO, bridge/TAP/IPAM, serial WS,
              REST + users/roles, React UI (wizard, hardware, storage, activity)
      skip:   optional ZFS backend
      open:   same Linux KVM boot as v0.1 (ISO install from the browser)
              procedure: upload ISO in Storage, wizard create+start; or scripts/linux-iso-guest.sh
              needs: hypervisor-fw (vmm.firmware) on the Linux node

v2.0  phase 5      cluster + HA  (+ phase 6 HCI if replica/RBD is in play)
      done:   join/leave, quorum/fence, migrate, replica volumes, storage-aware HA
      proof:  HA restart tests (`three_node_ha_restarts_elsewhere`,
              `replicated_volume_ha_prefers_replica_holder`)
      open:   3-node demo on Linux (kill a box; guest restarts on a replica holder)

v3.0  phase 7      flashable node image (Proxmox-style)
      done:   Debian mkosi overlay, systemd, firstboot, kvm check, pertisk-install
      path:   sudo ./scripts/install-node.sh  (existing Linux)
              ./scripts/build-iso.sh          (Linux + mkosi → out/*.iso)
              sudo ./scripts/flash.sh --image out/pertisk-node.iso --disk /dev/sdX --yes
      open:   proof on real hardware (flash USB, Alpine guest)
      not in v3.0: QEMU VGA / noVNC (separate; needed for Ubuntu Desktop/Windows)
